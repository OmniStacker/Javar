OAuth 2.0 最佳实践 & 面试要点

从理论到实战，从设计到面试的关键知识点。

令牌安全管理

  • ✓ Access Token 短期有效（15分钟-1小时）
  • ✓ Refresh Token 长期有效且加密存储
  • ✓ 使用 HTTPS 传输，防止中间人攻击
  • ✓ 实施 Token 轮换机制（Rotation）

会话存储策略

  • ✓ 全局会话：Redis集群（高可用）
  • ✓ 局部会话：各系统独立管理
  • ✓ 设置合理的过期时间（TTL）
  • ✓ 支持会话续期与主动销毁

授权码防护

  • ✓ Authorization Code 一次性使用
  • ✓ 添加 PKCE 扩展（移动端必备）
  • ✓ 验证 redirect_uri 白名单
  • ✓ 使用 state 参数防 CSRF 攻击

高可用架构

  • ✓ 认证中心集群部署（负载均衡）
  • ✓ 数据库主从复制 + 读写分离
  • ✓ 限流熔断（防止恶意攻击）
  • ✓ 监控告警（响应时间、成功率）

面试官最爱问的5个 SSO 问题

Q1: OAuth 2.0 和 Session 的区别？

A: OAuth 2.0 是无状态的令牌机制，适合分布式；Session 是有状态的服务端存储，适合单体应用。

Q2: 如何防止令牌被盗用？

A: ① HTTPS传输 ② 短期过期 ③ IP/设备指纹绑定 ④ 异常登录检测 ⑤ Refresh Token轮换

Q3: 全局会话存储在哪里？为什么？

A: 存储在Redis。原因：① 高性能（内存） ② 支持过期 ③ 集群共享 ④ 持久化备份

Q4: 单点退出如何保证所有系统同步？

A: ① 认证中心销毁全局会话 ② 通过消息队列（Kafka/RabbitMQ）广播 ③ 各系统监听并销毁局部会话

Q5: SSO系统的核心设计原则是什么？

A: 统一认证中心 + 全局会话管理 + 令牌信任机制，实现认证与业务解耦。

记住： SSO不是技术的堆砌，而是信任体系的构建。
