解密 `String s = new String("abc")`：它到底创建了几个对象？

面试官的经典陷阱：对象数量与存储位置的演变

关键转折：永久代 vs. 堆 | 共享 vs. 复制

1. JDK 6 及之前：永久代（PermGen）的时代

场景一：常量池中没有 "abc"

首次执行，会创建 2 个对象。

永久代 (PermGen)

Step 1
"abc" 对象
(在常量池中)
char[] value

Java 堆 (Heap)

Step 2
new String 对象
char[] value (引用)

➡️ 流程：先在永久代的字符串常量池创建 "abc" 对象，然后在堆中创建 `new String` 对象，该对象内部的 `value` 数组引用常量池中对象的 `value` 数组。

场景二：常量池中已有 "abc"

后续执行，仅创建 1 个对象。

永久代 (PermGen)
(已有"abc")

Java 堆 (Heap)

Only Step
new String 对象

➡️ 流程：因为常量池中已有 "abc"，所以只会在堆中创建 `new String` 对象。

2. JDK 7 / 8：常量池移入堆

最大的变化：字符串常量池（SCP）从永久代移到了Java堆内部。

Java 堆 (Heap)

场景一：常量池中没有 "abc" (创建 2 个对象)

常量池区域
"abc" 对象
普通对象区
new String 对象

➡️ 流程：两个对象都在堆里。一个在常量池区域，一个在普通区域。依然共享底层数组。

场景二：常量池中已有 "abc" (创建 1 个对象)

常量池区域
(已有"abc")
普通对象区
new String 对象

➡️ 流程：仅在堆的普通区域创建 `new String` 对象。

3. JDK 9+：字符串压缩与数组复制（重要转折！）

底层实现从 `char[]` 变为 `byte[]`（字符串压缩）。更重要的是，`new String("...")` 不再共享数组！

Java 堆 (Heap)

场景：常量池中没有 "abc" (创建 2 个对象)

常量池区域
"abc" 对象
byte[] A
普通对象区
new String 对象
byte[] B (复制品)

➡️ 核心变化：堆中的 `new String` 对象不再共享常量池对象的底层数组，而是复制一份全新的 `byte[]` 数组！

彩蛋：`intern()` 方法的经典案例

让我们通过一个经典例子，看看 `intern()` 如何在堆和常量池之间建立联系。

// 1. 在常量池中创建 "abc" 对象
String s1 = "abc";
// 2. 在堆中创建新对象，此时常量池中 "abc" 已存在
String s2 = new String("abc");
// 3. s2.intern() 发现常量池已有 "abc"，返回其引用
String s3 = s2.intern();

System.out.println(s1 == s2); // false (一个在常量池，一个在堆)
System.out.println(s1 == s3); // true (都指向常量池)

Java 堆 (Heap) 内存布局

"abc" 对象

s1

s3

new String 对象

s2

➡️ 结论：`s1` 和 `s3` 指向同一个常量池对象，而 `s2` 指向独立的堆对象。

`s2.intern()`的逻辑是：检查常量池，若存在内容相同的字符串，则返回池中对象的引用；否则，在池中创建该字符串并返回其引用。
