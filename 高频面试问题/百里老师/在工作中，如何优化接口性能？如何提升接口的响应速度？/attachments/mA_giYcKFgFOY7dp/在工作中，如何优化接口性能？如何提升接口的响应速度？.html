策略二：分页优化

大数据量分页的性能陷阱与解决方案

典型场景：订单列表分页查询

数据表：1000万条订单记录，用户要查看第 5000页（每页20条）

传统方案：OFFSET分页

SELECT * FROM orders
ORDER BY id
LIMIT 100000, 20

查询过程：

扫描 100,020 条记录
取20条

💡 必须扫描前面所有记录，越往后越慢

第1页: 5ms

第100页: 50ms

第5000页: 2000ms

优化方案：游标分页

SELECT * FROM orders
WHERE id > 100000
ORDER BY id LIMIT 20

查询过程：

索引快速跳过
直接取20条

💡 利用索引直接定位，性能稳定

第1页: 3ms

第100页: 3ms

第5000页: 3ms
