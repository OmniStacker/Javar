悲观锁 vs 乐观锁

核心区别：对并发冲突的“假设”不同

悲观锁

先加锁，再操作 (总假设会冲突)

synchronized, ReentrantLock

先操作，后验证 (总假设不冲突)

锁的艺术：场景与选择

低竞争场景

优先 乐观锁 (CAS) 或让 synchronized 保持在 偏向/轻量级，追求最低开销。

高竞争场景

果断使用 悲观锁，直接升级为 重量级锁，避免CPU空转。

读多写少

选择 读写锁 (ReadWriteLock)，允许多线程并发读，大幅提升吞吐量。

需要高级功能

使用 ReentrantLock，它提供中断、超时、公平性选择等 synchronized 不具备的功能。

没有最好的锁，只有最合适的场景
