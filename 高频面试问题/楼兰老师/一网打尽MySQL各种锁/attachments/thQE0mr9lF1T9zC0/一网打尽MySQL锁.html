锁的粒度：从大到小

全局锁

锁住整个库
场景: 全库备份
命令: `FTWRL`

表锁

锁住整张表
特点: 开销小, 并发低
引擎: MyISAM

行锁

锁住单行数据
特点: 并发高, 可能死锁
引擎: InnoDB

模式之争：悲观锁 vs 乐观锁

悲观锁

"世界充满危险，先锁上再说！"

先加锁，再操作。认为冲突总会发生。
适用于写多读少的场景。
实现: `SELECT ... FOR UPDATE`

乐观锁

"世界很美好，冲突只是偶然。"

先操作，提交时验证。认为冲突很少。
适用于读多写少的场景。
实现: 版本号(version)或时间戳

属性之分：共享锁 vs 排他锁

共享锁 (S锁 / 读锁)

"我读的时候，你也可以读。"

多个事务可同时读取同一资源。
读读共享，读写互斥。
实现: `LOCK IN SHARE MODE`

排他锁 (X锁 / 写锁)

"我写的时候，谁都别动！"

独占资源，其他事务无法读写。
写写互斥，读写互斥。
实现: `FOR UPDATE`

4 / 8

意向锁 (Intention Lock)

"我要对里面的东西动手了，你注意点！"

  • 本质: 表级锁，但服务于行锁。
  • 作用: 当事务想加表锁时，无需遍历所有行，只需检查意向锁，极大提升效率。
  • 机制: 当事务获取行锁时，InnoDB自动为其加上意向锁。
  • 分类: 意向共享锁 (IS), 意向排他锁 (IX)。

-- 事务A

> LOCK row 5 in table T;

(InnoDB 自动在表T上加了意向锁 IX)


-- 事务B (想锁整张表)

> LOCK TABLE T WRITE;

(InnoDB 发现表T上有意向锁, 立即判断有行锁冲突, 事务B进入等待)

记录锁 (Record Lock)

精准打击，只锁一行。

  • 目标: 锁定索引记录本身。
  • 触发: 通过唯一索引（主键、唯一键）进行等值查询时。
  • SELECT * FROM t WHERE id = 10 FOR UPDATE;
  • 效果: 只会锁定 `id=10` 这一行，不影响其他行。

表 user (id为主键)

ID: 5 Name: Alice
ID: 10 Name: Bob [LOCKED]
ID: 15 Name: Carol

间隙锁 & 临键锁

InnoDB的终极武器：解决幻读

  • 间隙锁 (Gap Lock): 锁定一个开区间，不锁记录本身。防止间隙中插入新数据。
  • 临键锁 (Next-Key Lock): 记录锁 + 间隙锁的组合，锁定一个左开右闭的区间。
  • 核心目的: 在 `REPEATABLE READ` 隔离级别下，防止幻读。
