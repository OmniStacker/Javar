这个“特工”懂得我们的“接头暗号”（解密算法），它能在字节码进入JVM前，悄悄完成解密。

核心方法：重写 findClass()

我们的“特工”主要在这里执行秘密任务。

四步走，完成“瞒天过海”：

  1. 定位文件：根据类名找到加密文件路径 (e.g., BillingService.class.encrypted)
  2. 读取密文：把加密文件的所有字节读入内存。
  3. 执行解密：调用解密算法，把密文还原成原始字节码。
  4. 定义类：调用 defineClass() 方法，把解密后的字节码交给JVM生成Class对象。

整个过程对JVM完全透明，它以为自己加载了一个普通类！

DecryptionClassLoader的核心实现

public class DecryptionClassLoader extends ClassLoader {
    // ... 构造函数 ...

    @Override
    protected Class findClass(String name) throws ClassNotFoundException {
        // 1. 定位并读取加密文件 -> encryptedBytes
        byte[] encryptedBytes = loadEncryptedClassData(name);
        
        if (encryptedBytes == null) {
            return super.findClass(name); // 找不到就交给父加载器
        }

        // 3. 执行解密
        byte[] decryptedBytes = CryptoUtil.decrypt(encryptedBytes);

        // 4. 定义类 (最关键的一步)
        System.out.println("成功解密并加载: " + name);
        return defineClass(name, decryptedBytes, 0, decryptedBytes.length);
    }
}

见证奇迹的时刻

如何使用我们的“特工”加载器

// 1. 创建我们的解密加载器
DecryptionClassLoader loader = new DecryptionClassLoader("path/to/encrypted/classes");

// 2. 使用它来加载我们的加密类 (注意：不能用import)
Class clazz = loader.loadClass("com.mycompany.secure.BillingServiceImpl");

// 3. 通过反射创建实例并调用方法
Object instance = clazz.newInstance();
Method method = clazz.getMethod("calculate");
method.invoke(instance);

// --- 运行结果 ---
// 成功解密并加载: com.mycompany.secure.BillingServiceImpl
// ====== 正在执行高度机密的核心计费算法 ======

我们成功欺骗了JVM，运行了加密的代码！
