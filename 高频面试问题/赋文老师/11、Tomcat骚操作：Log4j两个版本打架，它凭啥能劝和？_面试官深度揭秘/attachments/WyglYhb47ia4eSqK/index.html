💡 对双亲委派的"改良"

标准双亲委派

先父后子

1️⃣ 先让父加载器加载
2️⃣ 父加载不到再自己上

Tomcat WebAppClassLoader

先子后父

1️⃣ 先在自己地盘找
2️⃣ 找不到再交给父加载器

🎯 保证应用对自己依赖的最高控制权

🔄 WebAppClassLoader加载流程

检查缓存
看自己是否已经加载过这个类
优先自己加载
在 /WEB-INF/classes 和 /WEB-INF/lib 中查找
找到了？
直接返回，任务完成 ✅
没找到？
交给父加载器（Common ClassLoader）
层层向上
一直到Bootstrap ClassLoader

🤔 为什么要"先子后父"？

如果遵循标准双亲委派

Common ClassLoader的lib/目录有 Log4j 1.1

↓

所有应用都被强制使用1.1
自己打包的1.2或2.5永远没有出头之日

💪 反向委派确保每个应用
对自己依赖的完全控制权

💻 核心代码逻辑（简化版）

public Class<?> loadClass(String name) {
  // 1. 检查缓存
  if (已加载过) return 缓存;

  // 2. 🔥 核心：优先自己加载
  try {
    Class c = findClass(name); // 在WEB-INF中找
    if (c != null) return c; // 找到了!
  }

  // 3. 自己找不到，交给父加载器
  return super.loadClass(name);
}
🎯 "先子后父" 就体现在第2步！
