G1的"坑"：承诺为何失效？

-XX:+UseG1GC -XX:MaxGCPauseMillis=20

设置了停顿目标就安全了？太天真了！

✅ Young GC ≈ 20ms
⬇️ 流量突增 ⬇️
⚠️ Mixed GC ≈ 150ms
⬇️ 老年代被填满 ⬇️
🔥 Full GC ≈ 2.3秒（灾难）
失控原因：对象晋升速度 > 老年代回收速度 → 并发模式失败！

破局之道(一)：驯服G1

核心策略：让对象尽可能死在年轻代

1️⃣ 加大堆内存

-Xms8g
-Xmx8g

降低GC频率

2️⃣ 调新生代比例

-XX:G1Max
NewSize...=60

给年轻代更多空间

3️⃣ 调Region大小

-XX:G1Heap
RegionSize=4m

避免大对象晋升

4️⃣ 生命线：持续监控GC日志，分析晋升速率和Mixed GC频率

破局之道(二)：拥抱ZGC

🚀

杀手级特性：STW停顿 < 1ms

(无论堆是4GB还是400GB)

G1

停顿：15-150ms

TP99：不稳定 💔

ZGC

停顿：< 1ms

TP99：稳如磐石 ✅

代价：更高的CPU和内存开销，需JDK 15+
