#### **<font style="color:rgba(0, 0, 0, 0.96);">【方案一：线程池】</font>**<font style="color:rgba(0, 0, 0, 0.96);"> </font><font style="color:rgba(0, 0, 0, 0.96);">(PPT切换到第3页：线程池)</font>

**<font style="color:rgba(0, 0, 0, 0.96);">(手势引导，划分为左右两边)</font>**

<font style="color:rgba(0, 0, 0, 0.96);">“咱们先看方案一：线程池，我管它叫‘</font>**<font style="color:rgba(0, 0, 0, 0.96);">进程内异步</font>**<font style="color:rgba(0, 0, 0, 0.96);">’。”</font>

**<font style="color:rgba(0, 0, 0, 0.96);">(手指PPT左侧的优点)</font>**<font style="color:rgba(0, 0, 0, 0.96);">\ </font><font style="color:rgba(0, 0, 0, 0.96);">“它的优点就两个字：</font>**<font style="color:rgba(0, 0, 0, 0.96);">简单、快捷！</font>**<font style="color:rgba(0, 0, 0, 0.96);"> 任务提交方和执行方都在一个进程里，没有网络开销，几乎是零延迟。代码层面用一个 </font><code><font style="color:rgba(0, 0, 0, 0.96);background-color:rgba(175, 184, 193, 0.2);">@Async</font></code><font style="color:rgba(0, 0, 0, 0.96);"> 注解就搞定了，非常简单方便！”</font>

**<font style="color:rgba(0, 0, 0, 0.96);">(表情变得严肃，手指PPT右侧的硬伤)</font>**<font style="color:rgba(0, 0, 0, 0.96);">\ </font><font style="color:rgba(0, 0, 0, 0.96);">“但是！它的硬伤也是致命的！我总结为三点：”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“第一，</font>**<font style="color:rgba(0, 0, 0, 0.96);">数据会丢失！</font>**<font style="color:rgba(0, 0, 0, 0.96);"> 想象一下，你服务一重启，线程池队列里还没处理的任务，是不是全没了？未处理任务若是核心业务，那不就出大事了？”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“第二，</font>**<font style="color:rgba(0, 0, 0, 0.96);">耦合性太强！</font>**<font style="color:rgba(0, 0, 0, 0.96);"> 所有代码都在一个项目里，以后想把“发短信”功能拆成独立服务，那就得伤筋动骨地改代码。”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“第三，</font>**<font style="color:rgba(0, 0, 0, 0.96);">没有削峰能力！</font>**<font style="color:rgba(0, 0, 0, 0.96);"> </font><font style="color:rgba(0, 0, 0, 0.96);">双十一零点，瞬间进来10万个请求，线程池直接就满了，后面的任务全被拒绝，等于啥也没干！”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“所以结论就是：线程池，只适合那些</font>**<font style="color:rgba(0, 0, 0, 0.96);">不重要、允许丢、并且未来也不太会扩展</font>**<font style="color:rgba(0, 0, 0, 0.96);">的内部任务。它是个战术武器，不是战略武器！”</font>

#### **<font style="color:rgba(0, 0, 0, 0.96);">【方案二：MQ】</font>**<font style="color:rgba(0, 0, 0, 0.96);"> </font><font style="color:rgba(0, 0, 0, 0.96);">(PPT切换到第4页：MQ)</font>

**<font style="color:rgba(0, 0, 0, 0.96);">(语气变得从容、有深度)</font>**

<font style="color:rgba(0, 0, 0, 0.96);">“那想干大事，就得用更稳的方案：消息队列（MQ）！我称之为‘</font>**<font style="color:rgba(0, 0, 0, 0.96);">分布式异步</font>**<font style="color:rgba(0, 0, 0, 0.96);">’。”</font>

**<font style="color:rgba(0, 0, 0, 0.96);">(手指向PPT的流程图)</font>**<font style="color:rgba(0, 0, 0, 0.96);">\ </font><font style="color:rgba(0, 0, 0, 0.96);">“你看这个架构，订单服务只管把消息扔给MQ，它压根不关心谁去消费，怎么消费。下游的通知服务、积分服务，自己去MQ拿消息处理就行了。”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“它怎么解决线程池那三大硬伤的？”</font>

**<font style="color:rgba(0, 0, 0, 0.96);">(依次手指数出1, 2, 3，并指向PPT对应区域)</font>**<font style="color:rgba(0, 0, 0, 0.96);">\ </font><font style="color:rgba(0, 0, 0, 0.96);">“</font>**<font style="color:rgba(0, 0, 0, 0.96);">第一，不丢数据！</font>**<font style="color:rgba(0, 0, 0, 0.96);"> </font><font style="color:rgba(0, 0, 0, 0.96);">MQ有持久化机制，消息会存到硬盘上。消费者处理完了会发个‘ACK’确认，就算中途挂了，MQ也会把消息重新投递给别人，保证任务‘至少被执行一次’！”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“</font>**<font style="color:rgba(0, 0, 0, 0.96);">第二，完美解耦！</font>**<font style="color:rgba(0, 0, 0, 0.96);"> 生产者和消费者彻底分离，以后想加什么新功能，比如来个数据统计功能，让它也去订阅这个消息就行了，订单服务一行代码都不用改！”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“</font>**<font style="color:rgba(0, 0, 0, 0.96);">第三，削峰填谷！</font>**<font style="color:rgba(0, 0, 0, 0.96);"> MQ就是个巨大的蓄水池。双十一的洪峰流量打过来，订单服务瞬间生成10万条消息扔进MQ，然后就可以潇洒下班了。下游服务再根据自己的能力，慢悠悠地处理，系统稳如老狗！”</font>

<font style="color:rgba(0, 0, 0, 0.96);">“所以，MQ才是构建大型分布式系统的基石，是</font>**<font style="color:rgba(0, 0, 0, 0.96);">战略级</font>**<font style="color:rgba(0, 0, 0, 0.96);">的架构设计！”</font>
