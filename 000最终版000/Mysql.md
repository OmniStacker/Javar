## 1. 基础概念

### 1.1 数据库三大范式

**第一范式（1NF）**：原子性，字段不可再分
**第二范式（2NF）**：完全依赖，非主键字段完全依赖于主键
**第三范式（3NF）**：传递依赖，非主键字段不依赖于其他非主键字段

### 1.2 CHAR和VARCHAR的区别

| 特性 | CHAR | VARCHAR |
|------|------|---------|
| **存储方式** | 固定长度 | 可变长度 |
| **空间占用** | 可能浪费 | 节省空间 |
| **查询速度** | 较快 | 较慢 |
| **适用场景** | 长度固定 | 长度变化 |

### 1.3 MySQL为什么默认使用InnoDB

- 支持事务
- 支持行级锁
- 支持外键
- 支持MVCC
- 更好的并发性能

### 1.4 MySQL为什么默认使用RR隔离级别

- RR（Repeatable Read）提供更好的数据一致性
- 防止不可重复读
- 通过Next-Key Lock防止幻读

### 1.5 一条SQL的执行过程是怎样的？

1. 连接器：身份认证和权限验证
2. 查询缓存：命中缓存直接返回（MySQL 8.0已取消）
3. 分析器：词法分析、语法分析
4. 优化器：生成执行计划
5. 执行器：调用存储引擎接口执行

## 2. 索引

### 2.1 什么是索引？索引有哪些优缺点？

**定义**：索引是帮助MySQL高效获取数据的数据结构。

**优点**：
- 提高查询效率
- 保证数据唯一性
- 加速表连接
- 减少分组和排序时间

**缺点**：
- 占用磁盘空间
- 降低写操作速度
- 需要维护

### 2.2 B树和B+树的区别？

| 特性 | B树 | B+树 |
|------|-----|------|
| **节点存储** | 存数据和指针 | 只存指针 |
| **查询效率** | 不稳定 | 稳定 |
| **范围查询** | 效率低 | 效率高 |
| **叶子节点** | 不链表 | 链表 |

**MySQL索引底层结构为什么使用B+树**：
- 磁盘IO更少
- 查询效率更稳定
- 更适合范围查询

### 2.3 MySQL索引分类

- **主键索引**：主键，唯一且非空
- **唯一索引**：值唯一
- **普通索引**：普通索引
- **联合索引**：多个字段组合
- **全文索引**：全文搜索
- **空间索引**：地理数据

### 2.4 什么是覆盖索引？

**定义**：查询字段被索引覆盖，无需回表。

**优点**：
- 减少回表
- 提高查询效率

### 2.5 什么是最左前缀原则？

**定义**：联合索引从最左开始匹配，不能跳过中间字段。

**示例**：
```
索引：(a,b,c)
WHERE a=1 AND b=2 AND c=3  -- 有效
WHERE a=1 AND c=3          -- 无效，跳过b
```

### 2.6 索引失效的情况有哪些？

1. 使用函数
2. 使用LIKE以%开头
3. 使用OR
4. 类型转换
5. 使用!=或<>
6. 索引列参与运算
7. 使用NOT IN
8. 条件字段与数据库字段类型不匹配

### 2.7 什么时候不要使用索引？

1. 数据量小
2. 区分度低
3. 频繁更新的表
4. 查询返回大量数据

### 2.8 MySQL索引设计有哪些原则？

1. 选择区分度高的字段
2. 使用短索引
3. 联合索引顺序很重要
4. 避免过多索引
5. 定期重建索引

## 3. 锁

### 3.1 MySQL中有哪几种锁？

**按粒度**：
- **全局锁**：锁定整个数据库
- **表级锁**：锁定整张表
- **行级锁**：锁定单行

**按性质**：
- **共享锁（S锁）**：读锁
- **排他锁（X锁）**：写锁

**InnoDB行锁**：
- Record Lock：记录锁
- Gap Lock：间隙锁
- Next-Key Lock：记录+间隙

### 3.2 MySQL的行级锁锁的到底是什么？

- 锁定索引记录
- InnoDB通过索引来加锁
- 如果没有索引，会锁全表

### 3.3 MySQL只操作同一条记录也会死锁吗？

会。原因：
- 不同事务以不同顺序锁定
- 间隙锁导致
- 索引冲突

### 3.4 如何解决MySQL死锁问题？

1. 分析死锁日志
2. 统一访问顺序
3. 降低隔离级别
4. 使用更小的锁粒度
5. 避免事务过长

### 3.5 InnoDB存储引擎三大特性

1. **Insert Buffer**：插入缓冲
2. **Double Write**：双写
3. **Adaptive Hash Index**：自适应哈希索引

## 4. 事务

### 4.1 事务的隔离级别有哪些？

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|----------|------|------------|------|
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | 不可能 | 可能 | 可能 |
| Repeatable Read | 不可能 | 不可能 | 可能 |
| Serializable | 不可能 | 不可能 | 不可能 |

### 4.2 并发事务带来哪些问题？

1. **脏读**：读到未提交数据
2. **不可重复读**：同一查询结果不一致
3. **幻读**：同一查询返回不同行数

### 4.3 讲讲你对MVCC的理解

**MVCC（多版本并发控制）**：
- 通过数据版本实现读写不阻塞
- 每个事务看到的数据快照不同
- 通过Undo Log实现

**核心组件**：
- 隐藏列（DB_TRX_ID、DB_ROLL_PTR）
- Undo Log
- Read View

### 4.4 MySQLInnoDB的MVCC实现机制

1. 每行数据有两个隐藏列
2. Undo Log保存历史版本
3. Read View确定可见性
4. 通过版本链回溯

### 4.5 事务的ACID特性

- **原子性（Atomicity）**：Undo Log
- **一致性（Consistency）**：业务逻辑
- **隔离性（Isolation）**：MVCC、锁
- **持久性（Durability）**：Redo Log

## 6. 高可用与架构

### 6.1 MySQL有哪些高可用方案？

1. **主从复制**
2. **主主复制**
3. **MHA（Master High Availability）**
4. **Orchestrator**
5. **InnoDB Cluster**
6. **ProxySQL**

### 6.2 讲讲主从复制原理与延迟

**原理**：
1. Master记录Binlog
2. Slave I/O线程读取Binlog
3. Slave SQL线程重放日志

**延迟原因**：
- 网络延迟
- 大事务
- 单线程复制
- 硬件性能

### 6.3 说下你对分库分表的理解

**分库分表原因**：
- 单库数据量过大
- 单表数据量过大
- 并发量过高

**分片策略**：
- 按ID取模
- 按范围分片
- 按时间分片
- 按地理位置分片

**挑战**：
- 跨库查询
- 分布式事务
- 分页查询
- 排序聚合

### 6.4 分库分表下如何实现精准分页？

1. 使用分片键
2. 使用二次查询
3. 使用全局索引
4. 使用游标分页

### 6.5 分表后非分片键的查询、排序怎么处理？

1. 建立索引表
2. 使用ElasticSearch
3. 使用同步工具
4. 扫描所有分片

### 6.6 MySQL数据库备份的3种方式

2. **逻辑备份**：使用mysqldump

## 7. 常见问题

### 7.1 truncate、delete、drop的区别

| 特性 | truncate | delete | drop |
|------|----------|--------|------|
| **类型** | DDL | DML | DDL |
| **回滚** | 不可回滚 | 可回滚 | 不可回滚 |
| **速度** | 快 | 慢 | 最快 |
| **释放空间** | 是 | 否 | 是 |
| **条件** | 全表 | 可条件 | 全表 |

### 7.2 count(1)、count(*)与count(列名)的区别

- **count(*)**：统计所有行，最优
- **count(1)**：统计所有行，与count(*)相同
- **count(列名)**：统计非NULL值

### 7.3 MySQL中in和exists的区别

- **IN**：适合子查询结果集小
- **EXISTS**：适合外表数据量小

### 7.4 UNION与UNION ALL的区别？

- **UNION**：去重并排序
- **UNION ALL**：不去重，效率高
