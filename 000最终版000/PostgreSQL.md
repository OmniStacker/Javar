## 1. PostgreSQL概述

PostgreSQL是功能强大的开源关系型数据库，支持复杂查询、JSON、全文搜索等。

## 2. MVCC机制

### 2.1 什么是MVCC？

**MVCC（多版本并发控制）**：通过数据版本实现读写不阻塞。

### 2.2 MVCC如何工作？

**核心机制**：
- 每行数据保存多个版本
- 每个事务看到的数据快照不同
- 通过Undo Log实现版本回溯

**优势**：
- 读写不阻塞
- 避免锁竞争
- 提高并发性能

## 3. WAL预写日志

### 3.1 WAL机制是什么？

**WAL（Write-Ahead Logging）**：数据修改先写入日志，再写入数据文件。

### 3.2 如何保证数据持久性和一致性？

**机制**：
1. 修改先写入WAL日志
2. 日志写入成功后才提交事务
3. 崩溃时通过WAL恢复

**优势**：
- 保证数据持久性
- 减少磁盘写入次数
- 支持崩溃恢复

## 4. 事务隔离级别

### 4.1 PostgreSQL的事务隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|----------|------|------------|------|
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | 不可能 | 可能 | 可能 |
| Repeatable Read | 不可能 | 不可能 | 可能 |
| Serializable | 不可能 | 不可能 | 不可能 |

### 4.2 区别

- **Read Committed**：只能读已提交数据
- **Repeatable Read**：保证同一事务内数据一致性
- **Serializable**：最高隔离级别，完全串行化

## 5. 索引类型

### 5.1 PostgreSQL索引类型

1. **B-Tree**：默认索引，适用于等值查询和范围查询
2. **Hash**：仅支持等值查询
3. **GIN**：适用于数组、全文搜索
4. **GiST**：适用于地理空间数据
5. **SP-GiST**：空间分区索引
6. **BRIN**：块范围索引，适用于大表

### 5.2 使用场景

| 索引类型 | 适用场景 |
|----------|----------|
| B-Tree | 等值查询、范围查询、排序 |
| Hash | 等值查询 |
| GIN | 数组、全文搜索、JSONB |
| GiST | 地理空间数据、全文搜索 |
| BRIN | 大表、时间序列数据 |

## 6. JSON与JSONB

### 6.1 区别

| 特性 | JSON | JSONB |
|------|------|-------|
| **存储** | 文本格式 | 二进制格式 |
| **写入速度** | 较快 | 较慢 |
| **查询速度** | 较慢 | 较快 |
| **索引支持** | 不支持 | 支持 |
| **大小** | 原始大小 | 略大 |

### 6.2 适用场景

- **JSON**：写入频繁、查询较少
- **JSONB**：查询频繁、需要索引

## 7. 慢查询优化

### 7.1 诊断和优化流程

**诊断步骤**：
1. 开启慢查询日志
2. 使用EXPLAIN分析执行计划
3. 检查索引使用情况
4. 分析统计信息

**优化方法**：
1. 添加合适索引
2. 优化SQL语句
3. 调整参数配置
4. 考虑分区或分表
