## 1. Redis概述

### 1.1 什么是Redis？

Redis是一个开源的、基于内存的键值存储系统，支持多种数据结构。

### 1.2 Redis为什么这么快？

- 基于内存操作
- 单线程模型（避免了线程切换开销）
- 使用I/O多路复用
- 高效的数据结构

### 1.3 Redis是单线程还是多线程？

- **Redis 6之前**：单线程（处理网络请求和命令执行）
- **Redis 6+**：引入多线程（仅网络I/O多线程，命令执行仍是单线程）

### 1.4 Redis为什么把所有数据都放内存？

- 内存访问速度快
- 保证高性能
- 适合缓存、计数等场景

### 1.5 Redis有哪些常用应用场景？

1. 缓存
2. 会话管理
3. 计数器
4. 消息队列
5. 排行榜
6. 分布式锁

## 2. 数据类型

### 2.1 Redis数据类型及实现原理

| 数据类型 | 底层实现 | 适用场景 |
|----------|----------|----------|
| String | SDS | 缓存、计数器 |
| Hash | 哈希表 | 对象存储 |
| List | 双向链表/快速列表 | 消息队列、最新列表 |
| Set | 哈希表/整数集合 | 标签、好友关系 |
| ZSet | 跳表+哈希表 | 排行榜、延迟队列 |

### 2.2 Redis的Key和Value的设计原则

**Key设计**：
- 简洁明了
- 使用冒号分隔（如：user:123:profile）
- 控制长度

**Value设计**：
- 控制大小（大Key问题）
- 合理选择数据类型
- 避免复杂对象

## 3. 持久化机制

### 3.1 说说Redis的持久化机制

**RDB（快照）**：
- 定时快照
- 文件小，恢复快
- 可能丢失数据

**AOF（追加文件）**：
- 记录每个写命令
- 数据更安全
- 文件较大

**RDB+AOF结合**：
- 两者结合使用
- 兼顾性能和安全性

## 4. 过期策略与内存淘汰

### 4.1 Redis中key过期了一定会立即删除吗？

不会。Redis过期策略：

1. **定期删除**：随机检查过期key
2. **惰性删除**：获取key时检查是否过期

### 4.2 Redis的内存淘汰策略详解

**LRU（最近最少使用）**：
- 淘汰最近最少使用的数据

**LFU（最不经常使用）**：
- 淘汰访问频率最低的数据

**其他策略**：
- volatile-lru：对设置了过期时间的key使用LRU
- allkeys-lru：对所有key使用LRU
- volatile-ttl：淘汰剩余生存时间最短的key
- noeviction：不淘汰，返回错误

## 5. 高可用与集群

### 5.1 什么是Redis哨兵机制？

**哨兵（Sentinel）**：
- 监控Redis节点
- 自动故障转移
- 配置中心

### 5.2 REDIS集群的原理是什么？

**Redis Cluster**：
- 分片存储
- Gossip协议
- 自动故障转移
- 主从复制

### 5.3 怎么实现Redis的高可用？

1. 主从复制
2. 哨兵模式
3. 集群模式

### 5.4 REDIS集群会有写操作丢失吗？为什么？

可能丢失。原因：
- 异步复制
- 主节点故障切换
- 网络分区

### 5.5 缓存与数据库双写不一致问题如何解决？

**解决方案**：
1. 延迟双删
2. 设置过期时间
3. 使用分布式锁
4. 读写分离

## 6. 缓存问题

### 6.1 什么是缓存击穿、缓存穿透、缓存雪崩？

| 问题 | 定义 | 解决方案 |
|------|------|----------|
| **缓存击穿** | 热点key过期，大量请求打到数据库 | 设置永不过期、互斥锁 |
| **缓存穿透** | 查询不存在的数据 | 缓存空值、布隆过滤器 |
| **缓存雪崩** | 大量key同时过期 | 随机过期时间、永不过期 |

### 6.2 阿里面试：Redis缓存穿透怎么解决？

**解决方案**：
1. 缓存空值
2. 布隆过滤器
3. 参数校验
4. 限流熔断

## 7. 性能优化

### 7.1 Redis性能调优详解

**网络优化**：
- 使用Pipeline
- 批量操作
- 连接池

**内存优化**：
- 使用Hash
- 压缩数据
- 合理设置过期时间

**配置优化**：
- 合理设置maxmemory
- 开启持久化
- 监控内存使用

### 7.2 Redis实例抖动问题诊断与解决方案

**原因**：
- 内存不足
- 持久化阻塞
- 大Key操作
- 网络问题

**解决方案**：
- 监控内存
- 优化持久化
- 拆分大Key
- 网络优化

### 7.3 Redis的大Key问题如何解决？

**大Key定义**：
- String类型value > 10KB
- 其他类型元素 > 5000

**解决方案**：
1. 拆分数据
2. 压缩数据
3. 使用本地缓存
4. 异步处理

### 7.4 Redis的热Key问题如何解决？

**热Key定义**：
- 访问频率极高的key

**解决方案**：
1. 本地缓存
2. 分散热点
3. 使用Redis集群
4. 限流降级

## 8. 常见问题

### 8.1 Redis到底支不支持事务啊？

支持。Redis事务：
- MULTI：开启事务
- EXEC：执行事务
- DISCARD：放弃事务
- WATCH：监控key

**注意**：Redis事务不支持回滚。

### 8.2 说说你对PIPELINE的理解

**Pipeline**：
- 批量发送命令
- 减少网络往返
- 提高吞吐量

### 8.3 说说你对Redis操作原子性的理解

**原子性**：
- 单命令原子性
- 事务不保证原子性
- 使用Lua脚本保证原子性

### 8.4 如何用Redis统计用户访问量？

**方案**：
1. 使用HyperLogLog
2. 使用Bitmap
3. 使用Set

### 8.5 Redisson如果续锁失败怎么办？

**解决方案**：
1. 设置合理的锁超时时间
2. 使用看门狗机制
3. 监控锁状态
4. 降级处理

### 8.6 一个Redis实例最多能存放多少KEYS？

理论上限：2^32-1（约42.9亿）

### 8.7 Redis6为什么引入了多线程？

**原因**：
- 单线程处理网络I/O成为瓶颈
- 多线程提高网络I/O性能
- 命令执行仍是单线程

### 8.8 为什么Redis单线程模型效率也能那么高？

- 基于内存操作
- I/O多路复用
- 避免线程切换
- 高效数据结构
