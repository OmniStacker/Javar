## 1. JVM内存模型

### 1.1 JVM内存结构

**运行时数据区**：

1. **程序计数器（PC Register）**
   - 线程私有
   - 存储当前线程执行的字节码行号

2. **Java虚拟机栈（JVM Stack）**
   - 线程私有
   - 存储局部变量、方法调用
   - 栈帧：局部变量表、操作数栈、动态链接、方法出口

3. **本地方法栈（Native Method Stack）**
   - 线程私有
   - 为native方法服务

4. **堆（Heap）**
   - 线程共享
   - 存储对象实例
   - 垃圾回收主要区域
   - 分为：新生代（Eden、Survivor0、Survivor1）、老年代

5. **方法区（Method Area）**
   - 线程共享
   - 存储类信息、常量、静态变量
   - JDK 8+ 使用元空间（Metaspace）实现

### 1.2 JVM内存为什么要分代

**原因**：
- 不同对象的生命周期不同
- 新生代对象存活率低，老年代对象存活率高
- 分代回收提高效率

**分代策略**：
- 新生代：复制算法
- 老年代：标记清除/标记整理

### 1.3 Java进程占用的内存有哪些部分

1. **堆内存**：-Xmx设置
2. **栈内存**：线程栈大小
3. **元空间**：类元数据
4. **直接内存**：堆外内存
5. **JVM自身**：JIT代码、线程等

## 2. 垃圾回收

### 2.1 如何判断对象可以被回收

**可达性分析算法**：
- 从GC Roots出发，不可达的对象可以被回收

**GC Roots包括**：
- 局部变量引用
- 活动线程引用
- 静态变量引用
- JNI引用
- 虚拟机引导类加载器

### 2.2 什么是三色标记

**三色标记算法**：
- **黑色**：对象已检查过，成员对象也被检查过
- **灰色**：对象已检查过，但成员还没全部检查完成
- **白色**：对象没有被检查

**标记过程**：
1. 初始所有对象为白色
2. GC Roots直接引用对象变为灰色
3. 从灰色对象出发，将其引用对象变为灰色，自身变为黑色
4. 重复直到灰色集合为空
5. 剩余白色对象为不可达，可回收

**问题**：
- **浮动垃圾**：标记过不是垃圾的变成了垃圾（影响不大）
- **漏标问题**：需要的对象被回收（严重）

### 2.3 GC是任意时候都能进行的吗？

不是。GC需要满足一定条件：
- 内存不足时触发
- 程序主动调用System.gc()
- 某些GC策略需要STW（Stop The World）

### 2.4 年轻代为什么要划分两个Survivor区？

**原因**：
- 避免内存碎片
- 提高复制算法效率
- 解决半空间浪费问题

**流程**：
1. 对象在Eden区分配
2. Eden区满时，Minor GC，存活对象复制到Survivor0
3. 下次Eden区满时，Eden和Survivor0的存活对象复制到Survivor1
4. 清空Eden和Survivor0
5. 两个Survivor区交替使用

### 2.5 JVM中一次完整的GC流程

**Minor GC（年轻代）**：
1. Eden区满，触发Minor GC
2. 存活对象复制到Survivor区
3. 年龄达到阈值（默认15）晋升老年代

**Full GC（老年代）**：
1. 老年代空间不足
2. 元空间不足
3. 调用System.gc()
4. 统计新生代和老年代对象
5. 标记、清除/整理、回收

### 2.6 项目中如何选择垃圾回收器

| 回收器 | 适用场景 | 特点 |
|--------|----------|------|
| Serial | 单核、小内存 | 单线程、STW |
| Parallel | 多核、吞吐量优先 | 并行、STW |
| CMS | 低延迟 | 并发标记、浮动垃圾 |
| G1 | 大内存、低延迟 | 分区、可预测停顿 |
| ZGC | 超大堆、低延迟 | 并发、亚毫秒停顿 |

## 3. 类加载机制

### 3.1 说下类加载器机制与双亲委派

**类加载器**：
1. **Bootstrap ClassLoader**：启动类加载器，加载JRE/lib/rt.jar
2. **Extension ClassLoader**：扩展类加载器，加载JRE/lib/ext
3. **Application ClassLoader**：应用类加载器，加载classpath
4. **自定义ClassLoader**：用户自定义

**双亲委派模型**：
- 父类加载器优先加载
- 避免重复加载
- 保证核心类安全

**流程**：
1. 收到加载请求
2. 委派给父加载器
3. 父加载器无法加载时，自己加载

### 3.2 可以打破双亲委派机制吗？

可以。打破方式：
1. 重写loadClass()方法
2. 线程上下文类加载器
3. 热部署场景

### 3.3 Class常量池和运行时常量池的区别

| 特性 | Class常量池 | 运行时常量池 |
|------|-------------|--------------|
| **位置** | class文件 | 方法区 |
| **内容** | 字面量、符号引用 | 字面量、符号引用、直接引用 |
| **时机** | 编译时 | 运行时 |

### 3.4 字符串常量池是如何实现的

**JDK 8+**：
- 字符串常量池在堆中
- 使用哈希表存储
- intern()方法将字符串加入常量池

## 4. 对象分配与内存管理

### 4.1 对象一定分配在堆中吗？

不一定。对象可能分配在：
1. **堆**：常规分配
2. **栈上分配**：逃逸分析，小对象
3. **TLAB**：线程本地分配缓冲区

### 4.2 什么是TLAB

**TLAB（Thread Local Allocation Buffer）**：
- 线程本地的内存分配缓冲区
- 每个线程在堆上都有独立的TLAB
- 减少线程同步，提高分配速度

**优点**：
- 减少线程同步
- 提高分配速度
- 提高局部性

### 4.3 对象分配规则

1. **栈上分配**：逃逸分析，小对象
2. **TLAB分配**：线程本地
3. **Eden区分配**：常规对象
4. **老年代分配**：大对象、年龄达标对象

### 4.4 JVM对象分配内存如何保证线程安全

1. **CAS失败重试**
2. **TLAB分配**
3. **锁机制**

### 4.5 对象的结构是什么样的

**对象头**：
- Mark Word：哈希码、GC分代年龄、锁状态
- 类型指针：指向类元数据

**实例数据**：
- 对象属性

**对齐填充**：
- 8字节对齐

### 4.6 对象的大小如何计算

- 对象头：12或16字节
- 实例数据：属性大小之和
- 对齐填充：8字节对齐

### 4.7 强引用、软引用、弱引用、虚引用的区别

| 引用类型 | 回收时机 | 用途 |
|----------|----------|------|
| **强引用** | 不回收 | 常规对象 |
| **软引用** | 内存不足时 | 缓存 |
| **弱引用** | 下一次GC | 临时对象 |
| **虚引用** | 任何时候 | 对象回收跟踪 |

### 4.8 内存泄漏和内存溢出的区别

| 特性 | 内存泄漏 | 内存溢出 |
|------|----------|----------|
| **定义** | 对象无法被回收 | 内存不足 |
| **原因** | 长生命周期对象持有短生命周期对象引用 | 数据量过大、内存配置不足 |
| **表现** | 内存逐渐增长 | OOM |

## 5. JVM参数与调优

### 5.1 常用的JVM启动参数有哪些

**堆内存参数**：
- -Xms：初始堆大小
- -Xmx：最大堆大小
- -Xmn：新生代大小

**垃圾回收参数**：
- -XX:+UseG1GC：使用G1回收器
- -XX:+UseConcMarkSweepGC：使用CMS
- -XX:+UseParallelGC：使用Parallel

**其他参数**：
- -XX:MetaspaceSize：元空间初始大小
- -XX:MaxMetaspaceSize：元空间最大大小
- -XX:SurvivorRatio：Eden和Survivor比例
- -XX:MaxTenuringThreshold：晋升年龄阈值

### 5.2 设置堆内存XMX应该考虑哪些因素

1. 系统可用内存
2. 应用内存需求
3. 其他进程内存占用
4. 操作系统保留内存
5. 元空间、直接内存

### 5.3 JVM为什么使用元空间替换了永久代

**原因**：
- 永久代大小难确定
- 元空间使用本地内存，自动扩展
- 避免永久代OOM
- 更清晰的垃圾回收

### 5.4 Java进程占用的内存有哪些部分

1. **堆内存**：-Xmx设置
2. **栈内存**：线程栈大小
3. **元空间**：类元数据
4. **直接内存**：堆外内存
5. **JVM自身**：JIT代码、线程等

## 6. 常见问题排查

### 6.1 CPU百分百问题如何排查

**步骤**：
1. top命令找到Java进程ID
2. top -Hp 找到高CPU线程ID
3. jstack 打印线程栈
4. 将线程ID转换为16进制
5. 在jstack输出中查找对应线程
6. 分析代码定位问题

### 6.2 OOM一定会导致JVM退出吗？

不一定。OOM处理：
- 如果是非Heap区域OOM，JVM可能继续运行
- 如果是Heap OOM，且没有UncaughtExceptionHandler，JVM会退出
- 可以通过-XX:+ExitOnOutOfMemoryError控制

### 6.3 什么情况会导致JVM退出

1. 所有非守护线程结束
2. 调用System.exit()
3. OOM且无法处理
4. 发生致命错误

### 6.4 没有发生OOM，但是老年代在缓慢增长，可能的原因

1. 内存泄漏
2. 大对象分配
3. 元空间增长
4. 直接内存泄漏
5. 线程栈增长

### 6.5 工作中最常见的6种OOM问题

1. **Java heap space**：堆内存不足
2. **GC overhead limit exceeded**：GC时间过长
3. **Direct buffer memory**：直接内存不足
4. **unable to create new native thread**：线程数过多
5. **Metaspace**：元空间不足
6. **OutOfMemoryError: Requested array size exceeds VM limit**：数组过大
